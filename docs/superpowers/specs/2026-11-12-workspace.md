# 寻源工作区页面改版

用户已审阅两版交互草图并于 2026-11-12 授权实现、推送 GitHub 和部署。以第二版及本文件为准，原草图单价对比方案已取消。

## 确认结果

1. 编号只显示一次，网址带下划线、直接外链；真实名称选填，数字占位名不重复显示。保留旧数据，不做目录迁移或数据库清空。
2. 工作流只在工作台显示一次；工作台以采集状态、联系方式覆盖图表和简短待办为概览，不再显示完整供应商表或采购目标长列表。其他页面仅简短任务进度和停止入口。
3. 联系方式与人工复核合并为“联系与复核”，重点展示渠道、号码、用途、风险和需判断事项。首次人工联系记录保存后移入“后续处理”；取消不移动；待回复、已回复、报价待补充、已完成可持续更新。人工报价复核和联系进度独立，不能把找到邮箱或保存草稿等同已联系或已发送。
4. 有有效邮箱即可在询价草稿页起草，即使报价待复核；人工明确跳过者默认收起但可查看。保留草稿编辑、下载和未发送语义，多邮箱可明确选择收件人。
5. 报价洞察只展示整行折扣区间分布和真实历史趋势。模型来自当前账号规则及已存报价并集，不固定两项。字段覆盖目录价输入/输出/缓存、币种、单位、分组/倍率、官 key、自部署/运营商、官转聚合、条件、来源。不同口径不混算；缺基准或条件不清标待核对；无历史不补趋势。用户截图遮挡列明确不用纳入。
6. 日志按日期/批次分组，分页每页20条，短摘要、长详情展开，支持日期/网站/失败筛选。

## 实施边界

原生 HTML/CSS/JavaScript 与 Python 技术栈不变。采用现有 settings 保存账号隔离的跟进数据及收件人选择，避免生产 schema 迁移；写入前校验供应商归属，参数不能切换身份。报价统计从专门接口取得完整报价，不能使用云端列表前三条摘要。已有二维码 PR 不在本轮合并范围。

验收包括单元测试、真实本地 HTTP/浏览器回归、成员边界及线上部署状态与静态资源核对。生产不跑真实采集、不自动发消息。
