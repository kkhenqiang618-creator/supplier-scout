# Supplier Scout · 寻源供应商工作台

供应商模型报价与联系方式研究工具。支持本机运行和账号密码保护的云端部署。

## 云端结构

- Vercel Python HTTP Function：登录、名单、报价/联系方式、来源证据、导出与持久任务入队。
- 独立私有 Postgres：供应商、报价历史、会话、加密模型配置、任务租约及检查点。
- Vercel Linux Daemon：Moli 浏览器观察/操作循环；支持公告、联系入口及真实二维码解码。
- 联系方式模式保留原报价和人工结论。停止请求、发布中断和过期租约不会让旧进程覆盖新结果。

所有业务页面、接口和导出均需登录。没有注册入口或默认生产密码。会话仅保存随机 token 的 SHA256 摘要；模型 Key 使用独立环境密钥加密保存。源码不包含个人名单、数据库、截图或凭据。

## 团队账号与数据隔离

生产环境 `SCOUT_AUTH_USERS_JSON` 保存用户名到口令哈希的 JSON 映射，每项由 `auth.hash_password()` 生成。`SCOUT_ADMIN_USERNAME` 指定唯一超级管理员。每个账号的供应商、报价、联系方式、草稿、历史、日志、规则、任务和 API 配置都独立保存。新账号从空工作区开始，不继承旧共享 Key。升级前的共享数据归入指定的初始管理员工作区。

先应用 `cloud_schema.sql`，再应用 `cloud_tenants.sql` 启用所有权字段和 Postgres RLS。服务器在每个事务中通过参数化 `set_config(...,true)` 设置当前成员；内部认证和队列调度使用显式系统上下文。成员身份只来自已验证的会话，请求参数不能切换账号。数据库保留匿名 Data API 禁止访问的边界。

管理员侧栏有“成员询价总览”，可只读查看所有成员的数量、采集进度、供应商详情、报价、联系证据、询价草稿和最近日志。普通成员访问管理接口会得到403。管理员报表不返回成员模型服务配置或 Key。管理员平时的工作台仍显示自己的数据。

个人模型配置加密且不回显。采集任务复制发起人的加密配置，后续修改不会改变已开始任务的 Key。任务接口不返回配置快照。当前仍为全团队一次运行一个批次，任务进度对所属成员可见。

## 本机运行

```sh
python3 server.py --port 8765
```

现有本机工作区默认不启用外网登录保护。云端入口始终要求登录配置。数据目录 `data/` 不应删除或提交。

## 云端环境变量

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | 私有应用角色的 Postgres TLS 连接地址 |
| `SCOUT_ENCRYPTION_KEY` | 独立 Fernet 密钥，用于加密模型配置 |
| `SCOUT_ADMIN_USERNAME` | 唯一超级管理员用户名，由服务器配置 |
| `SCOUT_AUTH_USERS_JSON` | 多账号用户名到 `auth.hash_password()` 校验值的 JSON 映射；优先于旧单账号配置 |
| `SCOUT_AUTH_USERNAME` / `SCOUT_AUTH_PASSWORD_HASH` | 未设置多账号映射时的旧单账号配置 |
| `SCOUT_VERCEL_PROJECT_ID` / `SCOUT_VERCEL_TEAM_ID` | 当前项目的浏览器进程管理范围 |

云端浏览器启停使用当前生产项目的 Vercel OIDC 凭据；也支持独立的项目级 `SCOUT_VERCEL_SCALER_TOKEN`。凭据不返回浏览器，不写入源码。批次进度与停止标记保存在数据库。

`vercel.json` 默认不运行空闲浏览器实例。任务入队时启动，空闲60秒后停止，避免持续消耗免费内存额度。必须在生产环境验证授权与实际进程状态，不能仅凭 HTTP 200 判定采集成功。

数据库使用 `scout_private` 私有 schema，禁止匿名/普通 Data API 角色访问。先通过部署管理员创建独立应用登录角色，再应用 `cloud_schema.sql`。`scripts/import_local.py` 仅在云端供应商表为空时导入原 SQLite，并重置序列；API Key 单独加密迁移。不要把导入源文件上传到代码仓库。

Linux Daemon 镜像锁定 Python、Node、Moli 版本及下载校验值。二维码使用 Node 解码，macOS 本机保留 Vision。云端文件上传上限3MiB；本机保持5MiB。

## 验证

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```

云端数据库集成测试仅在迁移前的临时空项目中通过 `SCOUT_TEST_DATABASE_URL` 启用。不要对真实名单执行破坏性初始化。

邮件目前仅生成草稿，由人工发送；飞书自动同步和定时报表尚未接通。

## 联系与后续处理

网站以编号和可直接打开的网址展示，真实名称选填。首次人工联系后，在“联系与复核”保存记录即可进入“后续处理”；待回复、已回复、报价待补充和已完成均可继续更新，并保留最近100条跟进历史。跟进数据保存在现有账号隔离的 settings 中，无需新增生产数据库字段。保存草稿不代表已联系或已发送。

“询价草稿”允许有有效邮箱但报价待复核的网站起草，可选择当前供应商的收件邮箱；明确人工跳过的网站默认收起。报价洞察从只读完整报价接口读取数据，按实际模型、币种、单位、资源类型与分组筛选；不确定条件、不同版本和冲突折扣保留待核对。历史趋势只连接同一实际模型和同一计价口径，缺失处断线。工作台以图表概览，运行日志每页20条，按日期分组并展开详情。

前端行为验证：`node --test tests/test_workspace_frontend.cjs`；管理员切换回归：`node tests/test_admin_frontend.cjs`。

## 联系采集的加载与故障说明

浏览器操作会在当前步骤内等待正文、公告或菜单内容稳定，最多额外等待6秒，并遵守单命令24秒上限。仍在加载或停留网站验证页时，由程序最多追加两次等待，不消耗模型观察次数；有其他可用导航的局部加载不会阻止继续查找。真实卡死页面尽快返回未响应状态。无表单的公告、菜单按钮和公开登录页面可只读查看，真实表单提交、支付、发送等仍禁止。

同一无变化页面的同一点击或导航最多执行两次，随后提示改查其他入口；滚动位置、不同控件分别识别。首页暂时性连接失败最多自动重试一次。联系列表及来源弹层区分域名、证书、HTTP错误、网络超时、验证页、访问规则、页面加载、重复动作和预算等原因，并保存对应网址与浏览器。旧记录尽可能从历史警告补充分类，不修改原业务数据。

开源作者、第三方项目及已关闭站点保留的联系渠道仍计为找到；用途和归属风险通过证据说明，不自动剔除。可靠性验证：`python tests/browser_contact_readiness.py`（真实Chrome，可用`SCOUT_CHROME_BIN`指定已安装浏览器），追加`--moli`验证Moli；全部使用本地夹具，不调用模型。

## 旧网址与新入口恢复

遇到官网域名升级公告时，程序只跟随公告明确关联的唯一公网新入口，最多两跳；验证新入口可读后继续采集，并保留原网址、公告依据和恢复记录。普通浏览器跳转仍沿用既有加载行为；第三方作者、联系网站或不相关广告不能改写供应商网址。错误页、验证页、含糊多目标、私网和循环跳转不会自动确认为新官网。

旧入口完全无法读取时，可在“联系与复核”的对应行点“更新网址”，填写已确认的新网址及依据。保存不会重置联系人、报价、人工结论或草稿；旧检查结果保留，需单独重采新入口。运行中禁止手动改址，同账号已有相同网址或旧值已变更时会阻止覆盖。旧地址与依据可在“来源与过程”查看，使用现有contact_result JSON，无需数据库迁移。

迁移验证：`python tests/browser_entry_recovery.py`（加`--moli`验证Moli）；编辑器异步导航回归：`SCOUT_TEST_URL=http://127.0.0.1:端口 node tests/browser_entry_editor.cjs`，仅接受隔离的本机测试服务。
